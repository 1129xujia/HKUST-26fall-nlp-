# D1 实验与指标协议

状态：评价口径已约定；指标计算器与实验执行器在后续阶段实现。
D1–D3 的离线 mock 运行不计入正式实验结果，显式脚本中的评分不能用作真实质量指标。

## 数据划分与预处理

1. 主数据集为 MultiDoc2Dial；保留官方可用划分和对话边界。
2. 当前只提供项目自编 synthetic mini 数据，不声称已经下载或核验官方数据。
3. 正式使用前记录来源 URL、版本或 commit、文件校验和、许可和使用限制。
4. 如果没有可用的官方有标签测试集，从可用验证数据中按 conversation_id 做固定留出；
   调参与最终评价对话不重叠，并公开划分文件与随机种子。
5. 生成每个用户轮次样本时，仅保留此前的历史，下一条客服回复作为参考，不传入在线流程。
6. 检索库构成遵循数据集协议并固定版本；对话标注不加入检索正文。
7. 字符窗口开发起点为 1200 字符、150 字符重叠；正式使用前检查 tokenizer 和证据截断情况。
8. 官方 span 到 passage 的映射以及独立证据分组必须可追溯，重叠窗口按可替代证据处理。

## 固定条件

- 随机种子 42。
- 各系统使用相同语料、切分、评价样本、生成模型、生成参数和最大证据上下文预算。
- Embedding、Reranker、LLM、Prompt 均记录版本；正式模型尚未指定。
- 分支 top-k、候选数和 final top-k 在验证集调整后冻结。
- 缓存、预热、并发、硬件和计时边界保持一致。
- 保存全部请求的最终状态，不只报告成功作答子集。
- 真正无法获得的指标保留为未测量，不能编造为 0。

## 核心配置

configs/experiments.yaml 固定 E0–E7，每个 profile 从 baseline.yaml 合并。

- E0：当前问题、Dense、一次生成。
- E1：加 BM25；按查询顺序和检索分支顺序固定交替合并，保留来源并去重。
- E2：以 RRF 替代交替合并。
- E3：加 Cross-Encoder Reranker。
- E4：加历史对话驱动的查询改写；关闭子问题分解。
- E5：加 Evaluator / Policy；不重试，保留被拦截的候选答案供分析。
- E6：加 Optimizer，最多两次优化；失败时返回信息不足。
- E7：加人工转接包；无法接入真人时只评价转接决策与包完整性。

补充消融：仅当前问题、完整历史、查询改写、查询改写加分解。
E3–E7 当前只有配置，不具备正式运行条件。

## 指标定义

### 检索

令 G 为一个样本的必要证据组，每个组可以包含多个等价 passage；Rk 为前 k 条检索结果。

- Evidence Recall@k = 被 Rk 命中的证据组数 / 必要证据组总数。
- Hit@k = 是否至少命中一个必要证据组。
- Complete Coverage@k = 是否命中全部必要证据组。
- 在有证据标注的样本上做宏平均，并报告分母；无证据、澄清或越权操作样本不混入此分母。
- 单独统计各分支、融合候选和最终证据的指标。

### 回答

- 英文规范化：小写、去标点、去冠词 a/an/the、压缩空白；多参考答案取最佳匹配。
- EM：规范化后是否与参考答案完全一致。
- Token F1：规范化后的词级多重集 precision/recall 的调和平均。
- 对有参考答案的样本同时报告全样本结果与已作答子集结果；未作答的参考答案样本按 0 计。
- BLEU 作为可选补充，若使用需记录实现和版本。

### 引用与依据

- 引用有效率：输出引用中，属于当次提供证据集合的引用比例。
- 对 answered 但未给引用的结果单独记为失败，不能利用零引用获得高分。
- 依据正确率：被引用证据支持的可核验事实数 / 可核验事实总数。
- 幻觉率：不被证据支持或与证据矛盾的事实数 / 可核验事实总数。
- 另报告含至少一项无依据事实的已作答回复比例。
- 没有可核验事实的回复不强行定义事实级分数，单独报告数量。
- 模型判分保存判分 Prompt、模型、版本和逐项结果，并人工抽查。
- 在线 Evaluator 分数不直接作为唯一的离线质量指标。

### 对话、完成与转接

- 对话一致性：根据历史约束判分，并人工抽查指代和资格条件。
- 报告作答率、澄清率、信息不足率、转接率、错误率，分母均为全部请求。
- 有 expected_behavior 标注时报告相应决策准确率；官方数据无此标注则先补充标注方案。
- 没有真实业务完成标签时，不把生成回答或通过 Evaluator 等同于实际业务完成。

### 效率和成本

- 端到端延迟从接受输入到输出最终结果，报告平均值和 P95。
- 检索次数按每次完整 pipeline 调用计数；内部多个并行分支另报分支调用数。
- 模型调用次数和 Token 覆盖规划、生成、评价和优化全部模块。
- Token 区分服务端报告、估算和不可获得；mock 估算不用于正式金额比较。
- 金额估算需要固定计价依据和日期；未指定提供方前不估算价格。

## 结果可追溯

每次运行保存 run_id、sample_id、最终配置、代码版本与 dirty 状态、
数据/索引版本、模型和 Prompt 版本、逐样本预测、检索证据、评估反馈、动作和停止原因。
最终表格按上述配置重建，不手填没有运行记录的数值。
